    自动发布功能使用须知
    适用范围
    • 仅限 Linux x86_64 服务器，用于更新应用程序版本
    • 不支持 Windows 服务器 / ARM 架构服务器
    • 容器 仅支持 Tomcat（Java / H5）
    支持的更新包格式（严格遵循结构）
    类型格式结构要求
    Java 全量pcms.war标准 WAR 包
    Java 增量pcms.zip将 WEB-INF、module 等放入 pcms/ 文件夹，压缩pcms文件夹为 pcms.zip（切勿嵌套）
    H5 全量confApp.zip和pcms同级目录的H5，与 Java 增量相同逻辑：将 H5 资源放入 confApp/ 文件夹，压缩confApp文件夹为 confApp.zip不要嵌套目录
    DCS 文件pcms （C++ 可执行文件）C++的pcms文件
    Java 日志全量pcmsLog.war标准 WAR 包
    Java 日志增量pcmsLog.zip与 Java 增量相同：文件夹内为 pcmsLog/，压缩为 pcmsLog.zip

    特别注意：所有 ZIP 包必须在对应文件夹“那一层”压缩，禁止双层目录（例如 pcms/pcms/*）。

    数据库说明
    • 暂不支持 通过更新包执行 SQL 变更，请务必手动备份数据库并执行变更脚本。
    • 脚本内置备份命令使用绝对路径 /usr/local/PCMS/mysql/bin/mysqldump，若 MySQL 未安装在默认路径，备份将失败，需手动处理或修改脚本。
    • OceanBase 数据库使用 mysqldump 可能因租户内存/参数不兼容报错，后续优化，目前请手动备份。
    默认更新脚本逻辑
    1. 备份准备：在 /opt/upbak 创建以时间戳命名的备份目录。
    2. 读取配置：从 C++ 配置文件获取数据库连接信息。
    3. 数据库备份（失败则跳过，记录日志）。
    4. Java 全量：停止服务 → 备份原 pcms/ 及 pcms.war → 部署新包 → 还原 license、所有 .properties、会议室图片、轮播图等 → 清除缓存 → 重启。
    5. Java 增量：停止服务 → 备份 pcms/ → 解压 zip 覆盖 → 还原 license、配置文件、图片等 → 清除缓存 → 重启。
    6. H5 更新：停止服务 → 备份 confApp → 解压 zip 到 webapps → 清除缓存 → 重启。
    7. pcmsLog 全量/增量：同 Java 逻辑，但无 license/配置还原步骤。
    8. DCS 更新：停止服务 → 备份原 pcms 文件 → 覆盖新文件并赋予执行权限 → 重启。
    9. 健康检查：通过检测端口是否监听判断服务状态。
    常见问题与风险
    • 配置文件被还原：Java 更新时会自动还原原有 .properties 文件，若新版本增加了配置项，还原后可能缺少新配置导致启动失败。需登录服务器手动补充。
    • 数据库备份失败：如前述，非标准 MySQL 安装路径或 OceanBase 会导致备份中断，不影响更新但会失去自动备份。
    • 增量包嵌套错误：若 zip 包内层还包含一层同名目录（如 pcms/pcms/），更新时会覆盖错误，务必按规范打包。
    • 修改更新脚本时：所有去启动、停止、重启服务的命令，必须以systemctl start/restart/stop ****方式去写，不要写为service **** start/restart/stop，否则会导致系统认为更新错误
    建议：重要更新前先在测试环境验证更新包，并提前手动备份数据库及配置文件。
